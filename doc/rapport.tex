\section{Architecture du Projet}

L'application est structurée selon un modèle classique en couches (Layered Architecture), garantissant une séparation claire des responsabilités.

\subsection{Organisation Logicielle}
L'application suit une architecture en couches, dont voici les responsabilités principales :
\begin{itemize}
    \item \textbf{Couche de Présentation (Web/API) :} Gère les requêtes HTTP via les contrôleurs et assure le rendu des vues.
    \item \textbf{Couche de Service :} Centralise la logique métier et les règles de gestion.
    \item \textbf{Couche d'Accès aux Données :} Assure la persistance via Spring Data JPA.
    \item \textbf{DTO \& Utilitaires :} Facilitent le transfert de données et les transformations XML/XSLT.
\end{itemize}

\subsection{Stack Technique}
Le service repose sur une stack Java 21 moderne et robuste :
\begin{itemize}
    \item \textbf{Framework :} Spring Boot (Spring Web, Spring Data JPA).
    \item \textbf{Gestion des dépendances :} Maven.
    \item \textbf{Stockage :} MariaDB (Production) et H2 (Tests).
    \item \textbf{Traitement XML :} JAXB, Jackson-XML et Saxon-HE (XSLT/XPath).
    \item \textbf{Interface :} Thymeleaf pour le rendu des vues HTML dynamiques.
\end{itemize}

\section{Description de l'usine logicielle}

Afin d'assurer une livraison fluide et automatisée du service SEPA26, nous avons mis en place une usine logicielle complète intégrant l'Intégration Continue (CI) et le Déploiement Continu (CD).

\subsection{Surveillance et Déclenchement}
L'usine logicielle s'appuie sur une scrutation active (Polling SCM) du dépôt de gestion de version. Jenkins vérifie chaque minute (\texttt{* * * * *}) si de nouvelles modifications ont été apportées au code source. Si un changement est détecté, le cycle de build est automatiquement lancé.

\subsection{Chaîne de Build et Automatisation}
Le processus est orchestré par un \texttt{Jenkinsfile} (Pipeline) structuré en plusieurs étapes clés :

\begin{itemize}
    \item \textbf{Préparation :} Initialisation de l'environnement, création d'un réseau Docker dédié (\texttt{sepa-network}) pour isoler les communications et nettoyage des anciens conteneurs.
    \item \textbf{Gestion des Données (MariaDB) :} Lancement automatique d'un conteneur MariaDB. La persistance est assurée par un volume Docker et les accès sont sécurisés via l'utilisation des \textit{Credentials} Jenkins pour masquer les mots de passe.
    \item \textbf{Compilation et Packaging (Maven) :} Exécution de la commande \texttt{mvn package} qui assure la compilation, le passage des tests unitaires et d'intégration, et la génération de l'artefact exécutable.
    \item \textbf{Conteneurisation (Docker) :} Construction de l'image Docker de l'application intégrant l'artefact généré.
    \item \textbf{Déploiement :} Lancement du conteneur applicatif sur le port \texttt{8100}, lié dynamiquement à la base de données MariaDB via les variables d'environnement.
\end{itemize}

\subsection{Sécurité et Isolation}
L'architecture de l'usine logicielle privilégie la sécurité :
\begin{itemize}
    \item \textbf{Secrets :} Aucun mot de passe n'est stocké en clair dans les scripts ; Jenkins injecte dynamiquement les secrets au moment de l'exécution.
    \item \textbf{Réseau :} L'utilisation d'un réseau Docker \textit{bridge} assure que seul le serveur applicatif est exposé à l'extérieur, la base de données n'étant accessible que par l'application au sein du réseau privé Docker.
\end{itemize}

\newpage

\subsection{Maintenance et Redémarrage}
Grâce à l'automatisation via Jenkins et Docker, le redémarrage ou la mise à jour du service est simplifié :
\begin{itemize}
    \item \textbf{Redémarrage via Jenkins :} Une simple action \textit{"Lancer un build"} sur l'interface Jenkins suffit à déclencher le pipeline complet. Le script se charge de stopper les instances existantes, de recompiler le code et de relancer proprement les conteneurs MariaDB et SEPA26.
    \item \textbf{Redémarrage manuel :} En cas de besoin, il est également possible de redémarrer le service manuellement sur la VM via les commandes Docker (\texttt{docker restart servicesepa26}).
\end{itemize}

\section{Éléments Optionnels}
Nous avons ajouté quelques fonctionnalités pour rendre le service plus simple à utiliser depuis un navigateur :

\begin{itemize}
    \item \textbf{Formulaire d'insertion :} Il est possible d'envoyer un fichier XML directement depuis la page \url{/transfert} sans avoir à passer par une commande \texttt{curl}.
    \item \textbf{Bouton supprimer :} Sur la page des résumés (\url{/resume/html}), nous avons ajouté un bouton pour supprimer une transaction en un clic. C'est plus pratique que de forger une requête \texttt{DELETE} à la main.
    \item \textbf{Collection Postman :} Nous avons fournit le fichier \texttt{sepa26\_pepin\_ouattara.json} qui contient déjà toutes les requêtes prêtes à l'emploi pour tester le serveur (VM).
\end{itemize}
